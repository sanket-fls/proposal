# Proposal Engine

Paste a client brief. Get a proposal whose every number is traced to the actual hours of comparable past projects, with the questions you should ask before committing. Runs as a ChatGPT app (Apps SDK / MCP) and as a standalone page.

**The problem.** Agencies and consultancies write hundreds of proposals a year. Each takes a senior person half a day, and the price is still a gut feel. The delivery history that would make it accurate (what similar work *actually* took) sits in old timesheets nobody opens.

**What the engine does** — seven stages, each streamed to the screen as it runs:

| # | Stage | What happens | OpenAI used |
|---|---|---|---|
| 1 | Extract | Requirements pulled from the brief, each anchored to the exact words it came from; marked *asked for* vs *inferred from a pain point* | Responses API, structured outputs (fallback: rules) |
| 2 | Retrieve | The most similar past projects, by meaning, work coverage and industry | Embeddings (fallback: TF-IDF) |
| 3 | Estimate | Hours per requirement as P50/P90 of **actual** effort on comparable components, with that category's historical overrun already included | — (deterministic) |
| 4 | Schedule | Phases and weeks from effort and team capacity | — |
| 5 | Price | Pilot / Recommended / Comprehensive, with a confidence grade from the P90/P50 spread | — |
| 6 | Risk | Tight deadline vs evidence, no budget, vague scope words, integration dependencies, sensitive data, autonomy — each with the question to ask the client | — |
| 7 | Compose | The proposal text, streamed, using only the computed numbers | Responses API streaming (fallback: template) |

The model does judgement (reading, matching, writing). The code does arithmetic. No price is ever generated by a language model.

## Run

```bash
npm install
npm start            # http://localhost:8787
```

With OpenAI (extraction, embeddings and writing go live; everything else is unchanged):

```bash
OPENAI_API_KEY=sk-... npm start
```

Without a key the deterministic engine runs the whole pipeline from the delivery history, so the demo never depends on the network.

`PACE=0 npm start` removes the inter-event delays that make the live animation readable (the ChatGPT tool always runs at full speed and the widget replays the recorded timing).

## Connect to ChatGPT

1. `ngrok http 8787`
2. ChatGPT → Settings → Apps & Connectors → Advanced → **Developer mode** on.
3. Create a connector pointing at `https://<tunnel>/mcp` (no auth).
4. New chat, enable the connector, paste a brief: *"Build a proposal for this brief: …"*.

The widget replays the engine run inside ChatGPT and offers export, plus a follow-up that asks ChatGPT to draft the client-questions email.

## Delivery history

`data/history.json` holds 52 past projects / 231 components with estimated and actual hours, generated by `scripts/gen-history.js` (seeded, so numbers are stable). Replace it with real timesheet exports in the same shape:

```json
{ "id": "P-101", "client": "…", "industry": "Healthcare", "year": 2025, "title": "…", "summary": "…",
  "components": [{ "name": "Retrieval with citations", "category": "knowledge-base", "complexity": 2, "estimatedHours": 140, "actualHours": 171 }],
  "estimatedHours": 820, "actualHours": 964, "plannedWeeks": 9, "actualWeeks": 11, "outcome": "Live" }
```

Rates and team capacity live in `src/engine/taxonomy.js` (`RATES`, `TEAM`). They are placeholders.

## Layout

```
src/engine/   extract · retrieve · estimate · schedule · price · risk · compose · llm · index (orchestrator)
src/server.js Express: /mcp (ChatGPT), /api/run (SSE), /p/:id (printable), /p/:id.md
public/       app.html + engine-ui.js — one renderer for live runs and ChatGPT replays
data/         history.json (delivery history), proposals.json (saved runs)
```
