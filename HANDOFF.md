# Handoff: Proposal Engine

Read this first. It explains what exists, how it works, what is verified, and what to do next, in priority order. Submission deadline is in under 30 minutes.

## What this is

A ChatGPT app (Apps SDK / MCP) plus a standalone web page. The user pastes a client brief and gets a proposal where every hour and price is traced to the actual cost of comparable past projects, plus the questions to ask the client before committing.

Pitch: agencies write hundreds of proposals a year; each takes a senior person half a day and the price is still a guess. The engine prices from delivery history instead.

## How it works

`src/engine/index.js` runs seven stages and emits an event per step. The UI renders the events live (SSE) or replays them inside ChatGPT.

| Stage | File | OpenAI | Fallback |
|---|---|---|---|
| 1 Extract requirements | `extract.js` | Responses API, structured outputs | rules (keywords in `taxonomy.js`) |
| 2 Retrieve similar past projects | `retrieve.js` | Embeddings | TF-IDF |
| 3 Estimate P50/P90 hours from actuals | `estimate.js` | none | — |
| 4 Schedule phases | `schedule.js` | none | — |
| 5 Price 3 options | `price.js` | none | — |
| 6 Risk scan + client questions | `risk.js` | none | — |
| 7 Compose proposal text | `compose.js` | Responses API streaming | template |

Rule: the model does judgement, code does every number. No price is ever generated by the model.

OpenAI calls are in `src/engine/llm.js`. Everything works with no API key.

## Files

```
src/server.js        Express: /mcp (MCP, Streamable HTTP, stateless), /api/run (SSE live run),
                     /api/samples, /api/proposal/:id, /p/:id (printable), /p/:id.md
src/engine/          the seven stages + llm.js + taxonomy.js (categories, keywords, RATES, TEAM)
src/sample.js        three sample briefs (first one is the demo brief)
src/render.js        printable HTML and Markdown export
src/store.js         saves runs to data/proposals.json
public/app.html      the page (dark, editorial, animated chapters)
public/engine-ui.js  one renderer for live SSE and ChatGPT replay
data/history.json    52 synthetic past projects, 231 components with estimated vs actual hours
scripts/gen-history.js  regenerates history.json (seeded)
```

ChatGPT tool: `build_proposal({ brief })`. Returns `structuredContent` = full proposal including `events`; the widget (`ui://widget/proposal-engine.html`, `text/html+skybridge`) replays them. Widget uses `window.openai.toolOutput`, `openExternal`, `sendFollowUpMessage`.


- Live run ~7.7s end to end, all three sample briefs
- Widget replay with simulated `window.openai`, all export buttons fire
- Printable page, Markdown export, phone width

## Next steps, in order

1. **Connect to ChatGPT (do this first, 10 min).**
   - Terminal 1: `npm start`
   - Terminal 2: `ngrok http 8787`
   - ChatGPT: Settings → Apps & Connectors → Advanced → Developer mode on → create connector at `https://<ngrok-url>/mcp`, no auth
   - New chat, enable the connector, send: `Build a proposal for this brief:` + the sample brief from `src/sample.js`
   - If the tool is not called, send: `Use the proposal engine on that brief.`
   - If the widget is blank: check `openai/widgetCSP` in `src/server.js` (fonts.googleapis.com and fonts.gstatic.com are allowed); check the server log for errors.
2. **Test live mode once** with an API key. If extraction returns odd requirements, lower risk by removing the key; the rules fallback is demo-safe.
3. **Submit.** Repo is a clean single-commit git repo. Push it (`gh repo create proposal-engine --public --source=. --push`) and submit the link, plus a screen recording of a full run on the local page.
4. **Rehearse** `DEMO.md` once, out loud, timed.

## If something breaks

- `PACE=0 npm start` removes inter-event delays (debugging).
- `node scripts/gen-history.js` regenerates the history if `data/history.json` is damaged.
- `data/proposals.json` can be deleted safely.
- Rates/currency: `RATES` in `src/engine/taxonomy.js`. Currency is detected from the brief (India→INR, UAE→AED, UK→GBP, Singapore→SGD, else USD).

## Known limitations to state honestly if asked

- Delivery history is synthetic. It is the shape of a timesheet export; real data drops in the same JSON shape.
- Rates are placeholders.
- Risk scan is rule-based.
